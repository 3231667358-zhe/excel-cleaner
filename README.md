# Excel / CSV 自动整理工具 V1

一个命令行小工具：去掉表格里多余的空格、删掉整行空白的行、删掉完全重复的行。

**V1 只做这三件事**，不多做。原始文件永远不动，结果另存成一个新文件。

---

## 【项目简介】

Excel / CSV 表格在人工维护中很容易变脏：从别处粘贴来的数据带首尾空格，中间混着空行，同一条记录被录了两遍。这些看着不起眼的问题会让后面的筛选、统计、导入数据库全部出错，而逐行人工清理非常费时间。

这个工具用一条命令做完三件事，**原始文件永远不动**，结果另存为新文件，并打印一份处理统计。

---

## 【处理前 / 处理后】

`examples/` 里有一组演示数据，下面是当前代码跑出来的真实结果。

**处理前** `examples/sample_dirty.csv`（空格在代码块里看不见，下面用 `·` 把空格标出来）：

```csv
姓名·,·部门·,工号,在职年限
·张三·,·技术部·,1001,3
李四,·销售部·,1002,5
（这一行是空行）
·张三·,·技术部·,1001,3
王五,·技术部·,1003,0
赵六·,财务部,1004,2
```

**处理后** `examples/sample_dirty_cleaned.csv`：

```csv
姓名,部门,工号,在职年限
张三,技术部,1001,3
李四,销售部,1002,5
王五,技术部,1003,0
赵六,财务部,1004,2
```

三件事各自干了什么：首尾空格全部去掉（含表头）；第 4 行空行删掉；第 5 行与第 2 行完全重复，只留一条；`0` 是有效数据，没有被当成空值删掉。

运行方式和终端输出：

```bash
python3 clean.py examples/sample_dirty.csv
```

```

  结果文件：examples/sample_dirty_cleaned.csv

  汇总：读入 7 行 → 输出 5 行；去掉空白 7 处，删除重复 1 行，删除空白行 1 行
```

## 【核心特点】

- **原文件保护**：`-o` 指向源文件直接报错；输出文件已存在时不加 `--force` 一律拒绝覆盖；检查全部发生在建目录和写文件之前，被拒绝时磁盘上不会多出任何文件。跑完可以自己核对源文件 md5 未变。
- **CSV / TXT / XLSX 三种格式**：CSV 自动识别 UTF-8 和 GB18030（老中文表格常见编码），输出带 BOM，Windows 版 Excel 双击打开不乱码。
- **安全拒绝含公式 Excel**：删行会让公式引用错位，重写又分不清「公式」和「`=` 开头的文本」。所以扫到这两类单元格就直接拒绝整个文件、指出具体位置，而不是给出一份算错的表。
- **中文友好错误提示**：每个报错都是一句人话加上怎么改，不打印 Python 堆栈。

## 一、V1 能做什么

| 规则 | 说明 |
|---|---|
| 去首尾空白 | 每个单元格两端的空格、Tab、换行都去掉；第一行的列名同样处理 |
| 删除整行空白 | 去空白后整行都是空的（空单元格或空字符串），整行删掉；表头不适用 |
| 整行去重 | 内容完全相同的行只保留第一条；表头不参与去重，不会被误删 |

**空单元格本身不会被填任何东西**——不会填 0，不会填 NULL，也不会填其它占位符，就是留空。
只有**整行全空**才删；只要有一个单元格有内容，这行就保留。

支持的文件：`.csv` `.txt` `.xlsx`。**不支持 `.xlsm`**（宏文件），原因见下方「已知限制」。

**Excel 只接受「无公式的纯数据表」**：只要扫描到**真正的公式单元格**，或者**内容是 `=` 开头的文本单元格**，程序会直接拒绝处理、打印原因，**不会生成任何输出文件**。这是为了避免公式引用被破坏、以及文本被误写成公式。CSV / TXT 不受这条限制影响，行为完全不变。

不做的事（留给以后版本）：单个空单元格的填充、日期格式统一、单元格格式/颜色保留、多文件合并。

## 二、安装

### 只用 CSV

不用装任何东西，Ubuntu 自带 Python 3.12 直接能跑。

### 要处理 Excel（.xlsx）

需要一个第三方库 `openpyxl`。Ubuntu 24.04 推荐用 apt 装（系统没装 pip，用 apt 最省事）：

【Ubuntu】
```bash
sudo apt update
sudo apt install python3-openpyxl
```

装完验证一下：

【Ubuntu】
```bash
python3 -c "import openpyxl; print('openpyxl', openpyxl.__version__)"
```

能打印出版本号就是成功。如果报 `ModuleNotFoundError`，说明没装上，**不要继续跑 Excel 文件**，把报错发我。

> 如果你以后自己做虚拟环境（venv），也可以用 `pip install -r requirements.txt` 装同样的库。

【Ubuntu】


### 顺便存一份统计报告

【Ubuntu】
```bash
python3 clean.py 原始数据.csv --report 报告.txt
```

### 只看去空白 / 只看去重

【Ubuntu】
```bash
python3 clean.py 原始数据.csv --no-dedup
python3 clean.py 原始数据.csv --no-trim
```

### 查看全部参数

【Ubuntu】
```bash
python3 clean.py -h
```

完整参数表：

| 参数 | 作用 |
|---|---|
| `input` | 必填。要整理的源文件，支持 `.csv` `.txt` `.xlsx` |
| `-o` / `--output` | 结果写到哪。默认：`原文件名_cleaned.原后缀` |
| `--report` | 把统计结果另存一份文本文件 |
| `--no-trim` | 跳过「去首尾空白」 |
| `--no-dedup` | 跳过「整行去重」 |
| `--force` | 输出文件已存在时，允许覆盖它 |

## 四、安全设计

1. **不覆盖原始文件**：如果 `-o` 指向的就是源文件本身，程序直接报错退出。
2. **不覆盖已有文件**：输出文件已存在时默认拒绝，要覆盖必须显式加 `--force`。
3. **出错不装成功**：任何一步失败都会打印 `错误：...` 并以退出码 1 结束，不会留下半个结果文件还跟你说「完成了」。
4. **不做格式转换**：输入 CSV 就输出 CSV，输入 Excel 就输出 Excel，不会偷偷转格式。
5. **拒绝含公式的 Excel**：处理 `.xlsx` 前会先扫描所有工作表，发现真正的公式单元格、或内容是 `=` 开头的文本单元格，就直接拒绝整个文件。检查发生在**建目录和写文件之前**，所以被拒绝时磁盘上不会多出任何文件（连输出目录都不会被创建）。

## 六、已知限制（V1 故意不做的）

- **不支持 `.xlsm`**：本工具读写 Excel 的方式是「重建一个工作簿」，宏（VBA）没办法安全保留，硬做会静默丢宏。要用就把文件先在 Excel 里「另存为 `.xlsx`」。程序遇到 `.xlsm` 会直接报错退出，不会偷偷处理。
- **Excel 只搬数值和文字**：单元格颜色、字体、列宽、公式的计算结果缓存、合并单元格都不会保留到输出文件里。**注意：带公式的 Excel 根本不会被处理**——程序在重写之前就会检测到公式并拒绝整个文件，所以不存在「公式被原样保留」这回事。
- **含公式的 Excel 一律拒绝处理**：本工具删行后**不会**平移公式引用（`=SUM(B3:B4)` 这类引用会错位，实测删掉一行空行后引用会指向自己、造成循环引用）。V1 不修公式，检测到公式就直接拒绝整个文件。想处理这类表，先在 Excel 里把公式选择性粘贴成数值、另存为新的 `.xlsx`。
- **内容是 `=` 开头的文本单元格也一律拒绝处理**：V1 重写单元格时只搬运值、不记录单元格原始类型，区分不了「公式」和「`=` 开头的文本」，后者会被 openpyxl 误写成公式（Excel 打开可能显示 `#NAME?`）。所以同样直接拒绝，不做猜测。
- **默认第一行是表头**：如果你的文件第一行就是数据，这一行不会被去重、也不会被当空白行删掉（但它照样会去空白）。
- **空白行的判定很严格**：必须整行所有单元格都是空的才删。数值 `0`、文本 `"0"`、`0.0` 都不算空，不会被删。
- **整行去重要求每列都一样**：只差一列不算重复。
- **大文件会全部读进内存**：几十万行以内没问题，超大文件 V1 不保证。
- **只支持单个文件**：不做批量目录处理。
